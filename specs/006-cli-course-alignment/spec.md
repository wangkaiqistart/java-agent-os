## 用户场景与测试

### 用户故事1：发现命令并初始化工作区（优先级P1）

开发者通过统一入口查看可用操作、帮助和真实支持状态，离线初始化工作区，读取Agent配置；文件操作不需要启动完整运行时。

**优先原因**：准确的帮助、初始化与配置是后续对话的使用前提。
**独立测试**：无模型凭据、无外网的临时工作区中执行帮助、初始化、配置查看，核对产物、启动边界、退出码及零外呼。

**验收场景**：

1. **给定** 未初始化的可写目录，**当** 执行初始化，**那么** 创建约定的安全YAML和Agent目录；不覆盖已有内容、不建数据库、不解析凭据、不联网。
2. **给定** 两个合法Agent及一个非法配置，**当** 查看列表与详情，**那么** 展示安全元数据及固定诊断；非法项不描述为可用，其他合法项独立可见，不回显凭据/原始异常。
3. **给定** 任意本节注册的命令，**当** 请求帮助，**那么** 返回用途、参数、能力状态与成功退出码；不启动完整运行时、不创建会话或修改工作区。
4. **给定** 未知、重复、缺值或冲突选项，**当** 解析命令，**那么** 在副作用前非零退出，不回显可能携带敏感信息的原始参数。

### 用户故事2：持续与同一Agent对话（优先级P1）

开发者选择Agent进入交互，在同一进程发送多条消息并查看回复；每条消息经统一Agent入口处理，保持会话关联并可主动退出。

**优先原因**：逐行交互是本节相对US2单次stdin模式的主要用户价值。
**独立测试**：受控输入两条消息和退出指令，使用模型替身核对恰好两次处理、同会话与连续历史，再检查退出和资源释放。

**验收场景**：

1. **给定** 有效Profile与运行配置，**当** 交互发送两条安全消息，**那么** 使用同一会话、不同处理标识，第二次能使用第一轮安全历史，每条回复只输出一次。
2. **给定** 正在交互，**当** 输入去除首尾空白后的`/quit`或发生EOF，**那么** 退出并关闭本次运行资源；退出指令不入业务历史，不发起额外模型或工具调用。
3. **给定** 超限、非法编码或含已知密钥的消息，**当** 读取输入，**那么** 按既有安全契约拒绝；敏感原文不发送、不入库、不回显，结束本次处理，保留已安全提交的历史；交互空白行忽略且零处理，批处理空白保持拒绝。
4. **给定** 会话正在处理或工作区锁已被占用，**当** 新处理进入，**那么** 明确拒绝，不等待后偷偷重放，也不释放原持有者的锁。
5. **给定** 旧US2脚本使用stdin到EOF与JSON输出，**当** 使用本节批准的兼容模式，**那么** 保留原字段、显式会话恢复、退出码及零隐藏重试语义。终端默认交互，管道默认单次JSON，可显式选择模式。

### 用户故事3：恢复并隔离会话（优先级P1）

开发者在退出或重启后继续对应会话，同时隔离不同用户、渠道、Agent的数据，保留旧会话和审计关联。

**优先原因**：课件把幂等、隔离与持久化作为主要自动验收对象。
**独立测试**：临时库中重复相同身份、逐维改变身份、关闭重开；核对标识、完整消息/工具交换和审计关联。采用持久三元组→UUID绑定，复用V3分表历史。

**验收场景**：

1. **给定** 相同渠道、用户与Profile，**当** 使用三元组获取模式重复进入，**那么** 获得同一会话；任一维不同则会话不同，包含分隔符的字段不会造成身份碰撞。
2. **给定** 已保存两轮安全消息和工具交换，**当** 关闭资源、新建运行时读取，**那么** 身份、顺序、内容和审计关联完整，不重放旧模型或工具。
3. **给定** 显式恢复会话，**当** 标识未知、非法或Profile不匹配，**那么** 拒绝，不静默新建或重新绑定。
4. **给定** 旧V3临时库，**当** 按后续批准方案执行离线升级、重开和恢复演练，**那么** 原行与关联保留，不静默重新解释旧主键，不触碰个人库。

### 用户故事4：查看和管理真实能力（优先级P2）

开发者管理Agent定义，查看Provider、Tool、Session和运行状态的安全元数据，准确分辨已交付能力与后续课程能力。

**优先原因**：支持自助操作，避免空实现产生误导。
**独立测试**：临时配置和预置库测试创建/查询/删除，对未启用能力核对说明、非零退出和零副作用。12个命令入口全部可发现，完整Web业务和多渠道网关延期。

**验收场景**：

1. **给定** 合法Agent名称和安全配置，**当** 创建定义，**那么** 仅创建所选目录所需安全文件；重名、越界路径、软链接逃逸和敏感配置拒绝，既有文件不变。
2. **给定** Agent定义与会话历史，**当** 删除明确选中的定义，**那么** 不删除历史、审计、公共技能或其他目录，也不把旧会话重新绑定给其他Agent。
3. **给定** 未启用的未来能力，**当** 调用对应入口，**那么** 明确原因、后续归属和非零退出，不用固定空列表、空成功或伪造就绪通过验收。
4. **给定** 已启用的不同模式先后使用同一工作区，**当** 切换模式，**那么** 读取一致的配置与存储，原持久数据不丢失；“同一存储”不等于不同渠道自动共用同一会话。

### 边界情况

- 相同三元组并发首次创建，不能产生两条有效绑定或悬空引用；字段大小写、分隔符、空白、超长与敏感内容需确定规则。
- 首条就是`/quit`/EOF时，零处理/外呼；不创建空会话；运行时初始化建库与业务会话创建分别统计。
- 交互中模型失败、保存失败、中断或输出写入失败，不能假成功或自动重发；旧安全历史保留。
- 缺省Profile不存在、坏YAML/重名、缺凭据、只读目录、软链接工作区，均无隐式回退或敏感报错。
- `--profile`与旧`--agent`重复或矛盾时不得按参数顺序覆盖；显式`--session`仍受归属校验。
- 查询状态不得隐式建库、升级旧库或触发恢复写入；定义变更只影响后续启动快照。
- 无SecureDirectoryStream的平台仍明确拒绝正文读取，交互体验不构成弱化安全契约的理由。

## 需求

### 功能需求

- **FR-001**：提供统一AegisOS命令入口，清单、计数和能力状态可检查，帮助可见不代表业务已完成。
- **FR-002**：每个注册命令/命令组支持帮助；帮助为零模型/工具调用、零持久写入，不启动完整运行时。
- **FR-003**：支持明确的命令分派及用法错误，拒绝未知/重复/冲突选项，安全错误不回显原始参数。
- **FR-004**：初始化及文件型Profile操作采用轻路径；需Agent执行才启动相应运行时，状态查询按实际依赖加载，不一概启动全部服务。
- **FR-005**：初始化复用安全YAML和Agent目录规范，保持离线、无覆盖、无凭据解析、无数据库创建；失败只清理本次确定新建的内容。
- **FR-006**：Profile唯一来自`.aegisos/agents/<dir>/profile.yml`，`AGENT.md`承载任务指令；不恢复旧profiles目录或frontmatter回退。
- **FR-007**：Profile查询/创建/删除校验名称、批准根、配置与敏感内容；删除定义不删除会话、审计或公共技能，不递归执行未知目录内容。
- **FR-008**：Provider/Tool/Session/status查询展示实际安全元数据，区分“已配置/可执行/已连接/运行中”，不主动探测真实外部服务。
- **FR-009**：交互只负责读、提交、打印，消息全部调用已有统一Agent入口，不另实现Provider调用、ReAct循环或Tool执行。
- **FR-010**：交互逐条处理输入、可靠保存后再进入下一条，同一交互内Profile绑定不变。
- **FR-011**：交互模式的`/quit`和EOF正常结束，不作为业务消息；退出关闭本次启动的上下文、连接池、运行锁和传输资源。
- **FR-012**：沿用US2字节上限、严格编码、敏感拒绝和保存前检查；含密钥内容终止本次处理，不替换正文后继续。
- **FR-013**：本轮Profile必须显式选择，缺失即拒绝；不新增默认Profile，不按注册顺序猜Agent、Provider或模型。
- **FR-014**：明确`--profile`与`--agent`兼容及冲突规则；保留显式`--workspace`工作区隔离和`--session`归属校验。
- **FR-015**：本轮除帮助/版本外必须显式提供绝对工作区路径，不新增缺省，不搜索/写入其他个人工作区；路径严格校验。
- **FR-016**：未知、非法、错归属会话明确拒绝，不静默创建或重新绑定。
- **FR-017**：统一会话边界集中生成或绑定身份，相同三元组幂等、逐维隔离，并持久化及覆盖并发首次创建；不直接将未验证渠道输入拼作主键。
- **FR-018**：关闭重开保留角色、顺序、完整工具交换、处理状态、模型/工具审计关联，不重放历史副作用。
- **FR-019**：存储变更提供版本化手工建表、离线升级与恢复验收；不依赖自动DDL、启动静默升级或覆盖旧主键含义。
- **FR-020**：重命令显式采用覆盖真实跨模块实体/仓储的生产装配；持久写入及重开回读是验收依据，启动日志数字仅辅助。
- **FR-021**：显式路由、有限重试、前置审计、Tool经Sandbox、生命周期锁及安全错误保留，CLI不加隐式重试。
- **FR-022**：全局配置、Profile与技能绑定仅启动/重启加载；指令正文仍按US2安全契约逐轮读取。
- **FR-023**：交互展示与脚本输出有确定模式；结构化模式保留US2字段/退出码，诊断不污染机器可读stdout，各模式不泄露敏感信息。
- **FR-024**：新增命令不能令旧Web基础启动、US2管道与显式会话续聊无声失效；终端/管道行为按本次澄清确定。
- **FR-025**：未启用命令说明能力、原因与后续归属并非零退出，不以无行为成功冒充课程完成。
- **FR-026**：建立逐条课程追溯，区分复用、待补齐、批准偏差、延期、未验收；不按类/表存在判通过。
- **FR-027**：自动验收覆盖幂等/隔离/重开、输入退出和生产装配；帮助/分流及真实对话另列进程/人工验收，执行结果与方法分开记录。
- **FR-028**：每个故事有行为测试和适用的Maven test/package及质量/安全检查；真实天气默认关闭，按新授权与预算执行。

### 已批准的课程冲突处理

- **FR-029**：增加集中管理的持久`(channel, user, profile) → UUID`幂等绑定，保留V3分表和既有审计/恢复；不新增`messages_json`，明确记录这是存储形式偏差，不宣称课程列真实存在。旧显式UUID会话不自动猜测或补造身份。
- **FR-030**：注册全部12个叶命令和帮助；完成当前能力，`serve`仅复用现有Web基础，`gateway`显示未启用、原因和后续归属并非零退出。完整Web业务/多渠道以及课程完整三模式互通验收延期。
- **FR-031**：终端默认逐行交互，管道默认US2单次JSON，提供互斥的显式模式开关；保留`--agent`，新增`--profile`别名，两个选项同时出现即拒绝；无法可靠判断终端时使用单次模式或要求显式选择，不误启动交互。

### 关键实体

- **命令能力说明**：路径、用途、参数、轻重分类、启用状态、失败退出及后续归属。
- **CLI运行选项**：验证后的工作区、Profile、可选显式会话与输出模式；不承载消息正文或凭据。
- **会话身份**：渠道、用户、Profile组成唯一持久绑定，目标为UUID会话，历史仍为V3分表。
- **会话与处理历史**：已确认的身份、Profile绑定、消息/工具交换、处理及审计关联；复用003。
- **课程验收项**：页码/条目→FR/SC→场景→证据/偏差，详见[追溯表](course-traceability.md)。

## 成功标准

### 可测量结果

- **SC-001**：批准范围内全部命令帮助可用；帮助均零外呼、零会话创建和零文件变更，未启用命令无假成功。
- **SC-002**：两条有效消息加退出指令产生恰好两次处理、同一会话；退出/EOF额外外呼为零。
- **SC-003**：相同三元组重复进入及重开身份一致，逐维改变均隔离。
- **SC-004**：关闭重开后历史内容、角色、顺序、审计关联完全一致；初始化、查询与升级演练无旧数据丢失。
- **SC-005**：原US2脚本在批准兼容模式中保持字段与退出码；错误/敏感/锁竞争反例无未授权外呼或错误归属写入。
- **SC-006**：课程12项追溯入口均有FR/SC、场景与证据状态，全部偏差/延期可追溯，未执行不标通过。
- **SC-007**：获批范围行为回归、打包和约定质量/安全门禁全通过，US2回归保留；旧真实验收和本节新验收分别记录。

## 假设、约束与依赖

- 第18节是CLI代码课；工作分支基于US2归档，main与归档分支不动，用户PDF及其暂存blob保留。
- 保持Java21、九模块、Boot4.1.1/Spring AI2.0.1，不因课件旧版本降级。命令解析采用课程Picocli方向，具体依赖/实现留plan，本阶段不改POM。
- 既有持久会话、手工建表和显式装配优先复用，不创建竞争的会话系统；保留messages_json存储形式的批准偏差。
- 完整长期Memory、其他Tool、MCP/通知/调度、Web业务API及多IM通道不预先纳入，serve仅复用现有Web基础，gateway明确未启用。
- 功能产物尽量中文，配置YAML，关键代码实施时注释设计理由；敏感信息仅受控注入。
- 本阶段无Java变更、个人库操作、真实外呼或自动commit/push；进入implement前展示可审查任务及课程差异，沿用已有明确授权而不重复确认US2。
