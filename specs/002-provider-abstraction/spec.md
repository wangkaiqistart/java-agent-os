# 功能规格：LLM Provider 抽象

**功能分支**：`002-provider-abstraction`

**创建日期**：2026-10-19

**状态**：草稿

**输入**：根据 `docs/AiProgrammingGuide.md` 中的 US-1“对接 LLM（Provider 抽象）”编写：通过 Provider 抽象接入 LLM，并使用显式 Provider 选择。

## Clarifications

### Session 2026-10-19

- Q: Provider 配置（包括 Provider 名称、模型、端点和凭证引用）修改后应何时生效？ → A: 仅在运行时启动或显式重启时加载，配置修改需要重启后生效；US-1 不做动态重载。
- Q: Provider 调用因超时或临时网络错误失败时，US-1 是否应自动重试？ → A: 按 Provider 配置允许多次重试；每个 Provider 的重试次数有明确上限，仅临时网络或超时类错误可重试，每次尝试单独审计。
- Q: 当 Provider 配置没有填写重试次数时，默认应允许几次重试？ → A: 默认允许 0 次重试，只有配置明确指定时才重试。
- Q: 当请求只指定 Provider 名称但没有指定模型名称时，运行时应如何处理？ → A: 拒绝请求并返回缺少模型名称的配置错误；不从 Provider 配置或注册顺序隐式选择模型。
- Q: 当 Provider 调用的审计记录无法写入时，运行时应继续调用外部模型还是拒绝本次调用？ → A: 审计失败则拒绝外部调用，返回审计不可用错误；只有确认审计成功后才发送请求。

## 用户场景与测试

### 用户故事 1：调用已配置的 LLM Provider（优先级：P1）

作为 AegisOS 运行时用户，我希望通过指定名称的 Provider 发送模型请求，从而让 Agent 使用 LLM 时不依赖某一家厂商的接口。

**优先级理由**：模型调用是后续 ReAct 能力的基础。没有它，Agent 无法进行推理或生成响应。

**独立测试**：配置一个可用的 Provider 和模型，通过 Provider 能力提交提示词，验证返回结果包含模型输出和调用身份信息。该测试不依赖 ReAct、Memory、Tool 执行或 Web Service。

**验收场景**：

1. **假设**存在一个带有有效模型和凭证引用的 Provider，**当**请求指定该 Provider 和模型时，**那么**运行时向该 Provider 发送提示词，并返回标识所选 Provider 和模型的模型响应。
2. **假设**已配置的 Provider 返回正常响应，**当**响应包含用量信息时，**那么**运行时使可用用量值可见，并记录本次调用供审计。
3. **假设**已配置的 Provider 暂时不可用，**当**发起请求时，**那么**运行时返回能识别所选 Provider 的清晰错误，记录失败调用供审计，并且不静默选择其他 Provider。
4. **假设**Provider 配置允许有限次重试且请求因临时网络或超时错误失败，**当**仍有重试次数时，**那么**运行时按配置再次尝试；成功时返回响应，失败时返回明确错误，并为每次尝试分别记录审计信息。

### 用户故事 2：显式选择多个 Provider（优先级：P1）

作为运维人员，我希望每个请求或 Agent Profile 都明确指定要使用的 Provider，从而让多个 Provider 共存时仍能避免路由歧义。

**优先级理由**：显式选择可以防止多个 Provider 提供相似能力时请求误发到错误的厂商或模型。

**独立测试**：配置两个同类 Provider，分别发起指定 Provider 的请求，验证每个请求都到达指定 Provider；随后使用未知名称发起请求，验证返回约定错误。

**验收场景**：

1. **假设**存在两个名称不同的 Provider，**当**请求指定 Provider A 时，**那么**即使 Provider B 也可用，也只能选择 Provider A。
2. **假设**请求指定了未配置的 Provider，**当**运行时解析请求时，**那么**运行时返回可执行的未知 Provider 错误，并且不发起模型调用。
3. **假设**指定名称的 Provider 存在但所选模型不可用，**当**运行时解析请求时，**那么**运行时报告所请求的 Provider/模型组合不可用，不推断其他模型或 Provider。
4. **假设**请求只提供 Provider 名称而未提供模型名称，**当**运行时解析请求时，**那么**运行时拒绝请求并返回缺少模型名称的配置错误，不选择隐式默认模型。

### 用户故事 3：安全且可观测地运行 Provider 调用（优先级：P1）

作为运维人员，我希望每次 Provider 调用都可审计，同时凭证受到保护，从而能够诊断模型用量而不暴露敏感信息。

**优先级理由**：Provider 调用跨越信任边界，在被更高层 Agent 能力使用前必须可追溯且安全。

**独立测试**：使用由批准的运行时密钥来源提供的凭证，分别执行成功、拒绝和失败的 Provider 请求；检查审计记录及采集到的日志，验证必要元数据存在且凭证不存在。

**验收场景**：

1. **假设**Provider 请求已被接受，**当**调用完成时，**那么**一条审计记录包含调用结果、Provider 名称、模型名称、耗时信息和可用用量值，并且不保存凭证或完整的带敏感信息连接数据。
2. **假设**Provider 请求在访问外部模型前被拒绝，**当**返回拒绝结果时，**那么**拒绝原因可执行，审计记录能够识别被拒绝请求，且响应、审计数据和日志均不包含凭证值。
3. **假设**提示词或模型响应中包含类似凭证的文本，**当**运行时记录诊断信息时，**那么**诊断输出按照项目安全规则对敏感值脱敏或省略。
4. **假设**Provider 调用的审计记录无法建立，**当**请求准备发送到外部模型时，**那么**运行时拒绝本次调用并返回审计不可用错误，不得发送外部请求。

### 边界情况

- 请求未提供 Provider 名称：将其作为不完整请求拒绝，不得按实现类型、注册顺序或可用性选择默认 Provider。
- Provider 的凭证引用为空、格式错误或缺失：将 Provider 标记为不可用，返回清晰的配置错误，不得尝试未认证调用。
- Provider 返回不包含用量信息的响应：返回模型响应，并将用量记录为不可用，不得因此判定调用失败。
- Provider 超时或返回非成功结果：返回稳定的 Provider 错误类别，保留不含敏感值的失败上下文，并记录失败尝试。
- Provider 配置允许重试时：仅临时网络或超时类错误可以消耗重试次数；配置、认证、参数和未知 Provider 错误不得自动重试。
- 请求缺少模型名称：返回缺少模型名称的配置错误，不得使用 Provider 默认值或注册顺序隐式选择模型。
- 审计记录无法写入：返回审计不可用错误并拒绝外部模型调用；不得仅记录日志后继续发送请求。
- 同一个 Provider 名称被配置多次：配置校验必须报告冲突名称，不得任意选择其中一项。
- Provider 配置在运行中被修改：当前进程继续使用已加载的配置，修改内容必须在重启后才生效；US-1 不执行动态重载。
- 请求包含供后续 Agent 能力使用的可选 Tool schema：在支持时转换或透传 schema，但 Provider 调用不得因此执行 Tool。

## 需求

### 功能需求

- **FR-001**：运行时必须提供统一的 Provider 能力，US-1 的所有模型请求都通过该能力提交。
- **FR-002**：每个已配置 Provider 必须拥有唯一、明确且易识别的名称，供请求或 Agent Profile 引用。
- **FR-003**：运行时必须依据明确的 Provider 名称和所选模型解析请求，不得根据注册顺序、可用实现或其他隐式选择推断 Provider。
- **FR-004**：运行时必须支持配置至少一个 Provider 和模型，以完成有效模型请求；配置应包含凭证引用，并允许配置可选的端点覆盖。
- **FR-005**：运行时必须支持同时配置多个 Provider，并且每个请求只能路由到明确指定的 Provider。
- **FR-006**：未知 Provider、重复 Provider 名称、不可用模型、无效配置、超时或外部 Provider 失败时，运行时必须返回清晰且可执行的错误。
- **FR-006a**：Provider 可以配置非负的最大重试次数；未配置时默认值为 0。只有临时网络或超时类错误可以消耗重试次数，配置、认证、参数和未知 Provider 错误不得自动重试。
- **FR-006b**：请求必须明确提供模型名称；缺少模型名称时必须在外部调用前拒绝请求，不得隐式选择模型。
- **FR-007**：成功请求必须返回模型响应、所选 Provider 名称、模型名称，以及 Provider 提供的用量值。
- **FR-008**：每次被接受的 Provider 调用尝试都必须产生一条可审计的 LLM 调用记录，包含结果、Provider 名称、模型名称、时间信息和可用用量值。
- **FR-009**：审计存储可写时，被拒绝的请求必须以可审计形式记录，但不得产生外部模型调用。审计存储不可写时，返回审计不可用错误且不得外呼，不得声称拒绝记录已持久化。
- **FR-010**：凭证及其他敏感连接信息必须从批准的运行时密钥来源解析，且不得写入源码、文档、Agent 配置、审计记录、日志、生成物或版本控制。
- **FR-011**：Provider 错误和诊断信息必须保留识别 Provider 及失败类别所需的上下文，同时对凭证值和完整的带敏感信息连接字符串进行脱敏或省略。
- **FR-012**：Provider 能力可以为后续 ReAct 循环准备模型 Tool schema，但不得执行 Tool，也不得负责 ReAct 循环。
- **FR-013**：本功能必须提供聚焦自动化测试，覆盖单 Provider 调用、多 Provider 显式路由、未知或不可用 Provider、审计记录和敏感信息保护。
- **FR-014**：Provider 配置必须在运行时启动或显式重启时加载；运行中的配置修改不得动态影响当前进程，US-1 不提供动态重载。
- **FR-015**：本功能必须通过项目规定的测试和打包验证，之后 US-2 才能依赖它。
- **FR-016**：每次外部 Provider 尝试前必须先建立可写入的审计记录；审计记录无法建立时必须拒绝外部调用并返回审计不可用错误，不能仅依赖日志继续发送请求。

### 关键实体

- **Provider 配置**：命名的连接定义，包含 Provider 身份、支持的模型选择、必要时的端点信息，以及运行时凭证来源引用。
- **Provider 重试策略**：Provider 允许的最大重试次数和可重试的暂时性错误类别；未配置时最大重试次数为 0。
- **模型请求**：包含提示词、明确指定的 Provider 和模型、可选生成参数以及可选 Tool schema 声明。
- **模型响应**：包含模型内容、所选 Provider 和模型身份、结束信息，以及 Provider 提供时的用量值。
- **LLM 调用审计记录**：对接受或拒绝尝试的持久记录，包含结果、Provider/模型身份、时间、用量和安全的失败上下文。

## 成功标准

### 可度量结果

- **SC-001**：在聚焦自动化测试中，100% 的有效显式 Provider 请求都路由到指定 Provider，包括同时配置至少两个 Provider 的场景。
- **SC-002**：在聚焦自动化测试中，100% 的未知、重复或不可用 Provider/模型请求都能在误调用外部模型前失败，并返回可执行的错误类别。
- **SC-003**：审计存储正常可写的验证场景中，100% 接受或拒绝 Provider 尝试都能产生恰好一条对应的审计结果，包含可获得的 Provider/模型身份和时间信息；Provider 提供用量时必须记录用量。每次重试独立计为一次尝试；审计故障场景按 SC-009 和下述设计边界验收。
- **SC-004**：秘密扫描和日志断言在源码、文档、Agent 配置、审计记录、生成物和采集的诊断信息中发现的已配置凭证值数量为零。
- **SC-005**：Provider 能力必须通过聚焦自动化测试和项目宪法要求的完整测试/打包验证。独立验收上下文仅装配 Provider 调用、配置及持久审计所需组件，不注册或调用 ReAct、Memory、Tool 执行或 Web Service 的业务组件。此处约束业务运行路径；现有 storage 或 boot 的 Maven 依赖可以保留，但不得因此要求上述业务组件参与 Provider 调用或验收。aegisos-provider 不得直接依赖 aegisos-storage、aegisos-memory、aegisos-tool 或 aegisos-web。
- **SC-006**：在重试验证场景中，100% 的可重试临时错误都遵守 Provider 配置的重试上限，未配置重试次数的 Provider 不发生自动重试，且每次尝试都有独立审计记录。
- **SC-007**：配置修改后的运行中请求继续使用启动时加载的 Provider 配置，重启后才能观察到新配置；该行为在验证套件中 100% 可复现。
- **SC-008**：在缺少模型名称的验证场景中，100% 的请求都在外部调用前被拒绝，且不会选择隐式默认模型。
- **SC-009**：在建立前置审计记录时审计存储不可用的验证场景中，100% 的对应 Provider 尝试都在外部调用前失败，该次尝试的外部模型实际调用次数为零。

### 计划阶段一致性说明（2026-10-20）

上述审计可写条件用于消除 SC-003 与 SC-009 的物理冲突，不改变“前置审计失败禁止外呼”的已确认决策。计划补充的故障处理约定为：前置记录已提交、外部调用已发生后，如果审计终态写入失败，保留未确认记录，返回审计不可用及外部结果可能已发生的标记，不返回普通成功，不自动重发。该约定是计划阶段的技术设计补充，不是新增的用户澄清回答。

## 范围边界

本功能包含 Provider 注册、显式 Provider/模型选择、模型请求和响应处理、按 Provider 配置执行的有限重试、安全错误处理、带前置写入门槛的调用审计，以及为后续使用准备 Tool schema。

本功能不包含 ReAct 循环（US-2）、Memory 或统一 Memory 门面（US-3）、Tool 执行或 Sandbox 强制执行（US-4）、Web Service 端点（US-5）、Provider fallback/hedge racing、成本看板或 Agent 调度，也不包含运行时动态配置重载。

## 假设

- AegisOS 运行在可信应用环境中，并能够访问所选外部模型 Provider。
- Provider 凭证由环境变量或批准的密钥存储提供；本功能不定义密钥存储管理或轮换。
- Provider 配置在启动或显式重启时加载，运行期间不动态重载；Provider 的重试上限未配置时为 0，只有临时网络或超时类错误允许重试；流式、批量和 fallback 路由属于扩展工作。
- Provider 可以返回 Token 用量，但缺失用量是合法情况，应记录为不可用。
- 审计记录存储是 Provider 调用的前置依赖；审计不可用时采用失败关闭策略，不发送外部模型请求。
- 经过配置校验后，Provider 名称和模型名称作为区分大小写的标识符使用，重复名称无效。
- 现有项目模块布局和运行时基线属于实施阶段验证的项目约束，不是本规格新增的运行时行为。

## 依赖

- US-2 依赖 Provider 能力为每次 ReAct 迭代获取模型响应。
- 项目批准的模型客户端和协议适配器负责连接及消息/Tool schema 转换；AegisOS 仍负责 Provider 选择、审计和 Tool 执行边界。
- 项目宪法约束模块边界、显式 Provider 选择、敏感信息处理、配置生效契约、聚焦测试和完整构建验证。
