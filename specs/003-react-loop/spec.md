## 用户场景与测试

### 用户故事 1：完成并恢复不需要工具的对话（优先级：P1）

作为 Agent 使用者，我希望发送任务后得到回复，并在重新启动后继续同一个会话，不丢失已保存的对话，也不混入其他会话内容。

**优先级理由**：这是运行时最小闭环，也是工具推理和后续 Memory 能力的基础。

**独立测试**：使用固定返回文本的模型替身和临时持久化工作区，新建会话、连续发送消息、关闭并重新创建运行时、按同一身份继续消息；不需要外部模型或天气服务。

**验收场景**：

1. **假设** Agent 配置有效，**当**开始新对话并提交用户消息，**那么**运行时生成并返回稳定会话身份，为本次处理分配独立标识，选用配置中明确的 Provider/模型；无工具响应在第 1 次模型响应后完成。
2. **假设**同一会话连续提交两次消息，**当**第二次处理开始，**那么**模型收到允许使用的历史和当前请求，用户消息、模型回复按顺序保存；其他会话的数据不出现。
3. **假设**已完成对话且上下文提交成功，**当**进程重启后继续该会话，**那么**能恢复同一 Agent 的已保存历史；未知会话不能静默创建或恢复为其他会话。
4. **假设**Provider、上下文组装或保存发生故障，**当**结束处理，**那么**返回明确失败、保留已成功提交的状态并清理当前 Agent 上下文；保存失败不得宣称处理已成功持久化。
5. **假设**两个请求同时处理同一会话，**当**发生竞争，**那么**至多一个进入执行链，另一个得到会话忙结果；其他会话不被错误关联。

### 用户故事 2：让模型使用授权工具并继续推理（优先级：P1）

作为 Agent 使用者，我希望模型能调用允许的工具、读取结果并生成答案；失败时能知道原因，不重复产生工具副作用。

**优先级理由**：这是 ReAct 的行动与观察闭环；最小 http_get 同时为课程天气对话提供能力。

**独立测试**：模型替身先返回工具意图，再根据工具结果返回文本；工具使用本机受控服务或确定性替身，逐项验证执行顺序、权限、结果关联和持久审计。

**验收场景**：

1. **假设**模型在未到轮数上限时返回授权工具意图，**当**处理该响应，**那么**先保存模型响应，再经统一执行边界完成参数及 Sandbox 校验、开始审计提交、实际执行和终态审计提交，将结构化观察结果回填后进入下一轮。
2. **假设**同一模型响应含多个工具调用，**当**执行这些调用，**那么**按返回顺序串行执行，全部观察结果就绪后才发起下一次模型请求，调用标识和结果保持对应。
3. **假设**工具未知、未授权、参数无效、被 Sandbox 拒绝、执行失败或超时，**当**该错误已可靠记录，**那么**产生结构化失败观察供模型决定下一步；同一处理内相同调用标识不得被自动重放。
4. **假设**同一调用标识再次出现，**当**参数相同，**那么**复用已知观察而不再次执行；参数不同则记录调用冲突并终止；同一响应内重复标识须在任何工具执行前拒绝该响应。
5. **假设**工具开始审计不可提交，或执行后的终态审计不可提交，**当**发生故障，**那么**停止本次处理；前者零工具执行，后者标明结果不确定且不重放。
6. **假设**http_get 目标在部署授权范围内且响应有效，**当**执行请求，**那么**返回受大小和时间限制的结果并记录审计；越界地址、禁止目标及未批准重定向不产生越界请求。

### 用户故事 3：在上限和错误边界内停止并追踪全过程（优先级：P1）

作为运维人员，我希望循环有明确终点，并能关联模型调用、工具决策和停止原因，判断处理是完成、未完成还是失败。

**优先级理由**：防止无限推理、隐藏重试和无法追溯的外部操作。

**独立测试**：分别构造无工具文本、永不收敛、工具失败、Provider 失败、审计失败和重启中断；只使用测试模型、测试工具和临时存储。

**验收场景**：

1. **假设**上限为 10 且每次模型响应都要求工具，**当**第 10 次响应返回，**那么**记录该响应并返回达到上限，模型响应次数为 10、模型逻辑请求为 10，工具最多执行前 9 次响应中的调用，第 10 次响应中的工具执行次数为 0。
2. **假设**上限为 1，**当**第 1 次响应含工具意图，**那么**不执行工具并返回未完成；若该响应只有最终文本，则正常完成。
3. **假设**Provider 在自身有限重试后仍失败，**当**错误到达循环，**那么**停止本次处理，保留该 Provider 请求标识和安全错误，不在循环外增加重试或切换模型。
4. **假设**模型在同一响应中返回文本及工具意图，**当**未达到上限，**那么**保留两者并处理工具，不能把附带文本误当作最终完成；空文本且无工具的响应为错误。
5. **假设**进程在某次处理期间退出，**当**重新启动并恢复会话，**那么**已提交历史仍可用，未完成处理被识别为中断；未确认完成的工具不自动重新执行。
6. **假设**同一工作线程先后处理不同 Agent，或发生异常，**当**每次处理结束，**那么**当前 Agent 上下文均已清空，后续处理看不到此前 Profile。

### 用户故事 4：使用最新指令和受控历史形成上下文（优先级：P1）

作为 Agent 配置维护者，我希望修改受控指令文件后下一次模型请求就能使用最新内容，同时保持运行参数稳定、历史有界、缺失文件有明确反馈。

**优先级理由**：解决课程强调的上下文膨胀、指令变化不生效和配置静默缺失问题。

**独立测试**：使用临时文件、固定时钟、可控容量预算与内存/持久化替身，验证上下文顺序、逐次读取、截断、文件边界及跨会话隔离。

**验收场景**：

1. **假设**配置具有角色设定、Agent 指令、Bootstrap 和绑定 Skill，**当**构建上下文，**那么**先形成系统指令，再加入可选长期记忆、允许历史和当前消息，携带授权工具说明；系统指令末尾包含当前日期、时间及明确时区。
2. **假设**上下文刚构建完成，**当**修改已引用的指令或 SKILL.md 正文后再次构建，**那么**下一次构建读取新正文；修改 profile.yml、Provider 连接或技能绑定关系则需重启后生效。
3. **假设**Profile 显式引用的文件或已绑定 SKILL.md 缺失/不可读，**当**构建上下文，**那么**在模型调用前明确失败；未显式引用的约定 Bootstrap 文件缺失至少产生可定位的警告。
4. **假设**历史超过允许轮数或容量，**当**裁剪发送视图，**那么**保留系统指令和当前请求，优先保留最近完整消息组、移除最早非系统历史并记录截断；不删除持久历史、不自动总结、不留下孤立工具结果。
5. **假设**历史已全部移除但必保留内容仍超预算，**当**尝试构建，**那么**返回上下文超限并零模型外呼，不能静默截短系统指令、当前请求或 Skill 正文。
6. **假设**长期记忆尚未启用，**当**运行普通对话，**那么**仍可完成；启用时所有会话/长期记忆访问均经统一 Memory 门面，不能从循环直接读取其他会话或某个具体后端。
7. **假设**受控目录中的文件或软连接在启动后被改为越界目标，**当**下一次构建，**那么**重新校验实际路径并拒绝读取越界正文。

### 用户故事 5：从终端验证天气对话（优先级：P2）

作为本机开发者，我希望初始化非敏感工作区并手动开始或继续对话，实际观察“询问天气 → 查天气 → 给建议”，验证 US1 与 US2 的完整衔接。

**优先级理由**：项目现有 US2 指引要求最小 CLI；课程第 7 页要求真实天气对话验收。该入口复用统一处理链，不扩展为 Web 或调度平台。

**独立测试**：通过命令行测试驱动使用本机模型/天气替身及临时工作区，验证初始化、会话身份输出、再次进入同一会话和失败提示；真实外呼单独显式启用。

**验收场景**：

1. **假设**工作区为空，**当**执行初始化，**那么**生成必要目录和不含真实凭据的 YAML 示例；已有文件不被静默覆盖。
2. **假设**配置合法且有允许的天气查询工具，**当**从终端发送问题，**那么**经统一 Agent 处理入口运行并显示回复、会话身份及处理状态；指定既有身份可继续会话。
3. **假设**真实验收条件未满足，**当**运行默认测试或未显式启用的验收，**那么**真实模型/天气外呼次数为 0，真实验收状态为未执行，不能记作通过。
4. **假设**真实验收已明确启用、凭据和目标天气地址通过受控方式提供，**当**提交固定天气问题并继续询问建议，**那么**真实模型至少提出一次 http_get 调用、工具得到有效天气数据，模型结合结果返回非空建议；模型与工具审计可按同一会话和本次处理关联，并在存储重开后读到。

### 边界情况

- 非法或未知会话、会话与 Agent 不匹配、配置缺失：零外呼，返回固定安全错误；US1 的追踪标识格式合法不代表 US2 的持久化会话存在。
- 迭代上限、历史上限非法：拒绝配置；默认最大迭代次数 10、历史窗口 20 个完整用户处理轮次。
- 系统指令或当前请求单独超预算：明确拒绝，不自动删除、总结或追加模型请求。
- 达到上限但响应中仍有工具意图：保存为未完成状态，后续上下文排除未闭合工具交换组，不伪造工具成功结果。
- 工具结果超限、非预期格式或超时：产生受限结构化错误；超时不代表外部操作已取消，结果不明时禁止自动重放。
- 过程写入、审计提交或最终保存失败：停止后续外呼，不把未提交的数据描述为已保存。
- 中断恢复、并发处理、重复消息、重复工具标识：区分会话、处理和工具调用身份；新提交有新处理身份，相同工具调用的去重不跨会话猜测。
- 敏感凭据出现在消息、文件或结果中：检测到已知运行时凭据或可识别敏感载体时，立即拒绝当前处理；该内容不发送、不入库、不回显，只返回固定安全错误，并保留此前已安全提交的历史。
- 模型要求 Shell、文件写入、MCP、通知或其他未提供工具：拒绝并回填安全错误，不能借本轮最小工具能力执行。

## 需求

### 功能需求

以下保留原 FR-001～FR-014 的职责及五项已确认语义，并新增课程补齐需求。具体验收索引见 [课程追溯表](course-traceability.md)。

- **FR-001**：提供统一 Agent 处理入口，由项目控制 ReAct 调度，接收会话、用户消息和已注册 Agent，返回最终结果或明确的未完成/失败结果。
- **FR-002**：每轮按“组装上下文 → 调用明确的 Provider/模型 → 保存模型响应 → 判断终止或工具决策 → 受控工具执行 → 保存观察结果”推进。
- **FR-003**：按发生顺序持久化用户消息、模型响应和工具观察；会话互相隔离，后续推理和恢复只使用已成功提交的状态。
- **FR-004**：无工具意图且文本有效时立即结束，不发起下一次模型请求；文本与工具意图同时存在时保留二者并继续受控流程。
- **FR-005**：同一响应中的多个工具调用按模型顺序串行执行；同一处理内同一调用标识最多实际执行一次。
- **FR-006**：观察结果保持工具标识、名称、成功/失败状态与受限结果，供后续模型请求使用；不把自由异常正文当作结果。
- **FR-007**：最大迭代次数可配置、默认 10；每次成功取得并接受的 Provider 响应计 1 次，第 1 次响应为第 1 次；第 N 次响应无工具则可完成，有工具则返回达到上限，不执行该响应中的工具，也不发起第 N+1 次请求。
- **FR-008**：上下文/Provider 失败终止本次处理；可审计的工具业务失败、拒绝和超时回填结构化观察，由模型决定下一步；同一调用不得自动重试。
- **FR-009**：工具调度只能发生在项目控制的统一执行边界，模型客户端不得自动执行工具或在内部触发下一轮推理。
- **FR-010**：模型请求、工具决策、工具结果、截断及终止均可关联会话和独立处理身份，记录不得包含敏感凭据、提示词正文或原始厂商异常。
- **FR-011**：发送上下文有明确轮数与容量预算；保持系统指令和当前请求，优先保留最近完整历史，记录截断，不自动总结，不删除持久化原始历史。
- **FR-012**：提供覆盖无工具、单工具、多工具、多轮、拒绝、失败、上限和恢复的可重复验收场景；默认场景不依赖外部真实服务。
- **FR-013**：只有本功能各故事验收及项目交付质量门禁通过，后续依赖故事才能以其为已完成能力；默认测试通过不能替代真实天气验收通过。
- **FR-014**：运行时为新会话生成稳定唯一身份，持久化其 Agent 归属与上下文；按身份跨重启恢复，未知或归属不匹配的会话明确拒绝。
- **FR-015**：系统指令按“角色设定 → Agent 指令 → Bootstrap → 已绑定 Skill 正文 → 当前日期时间”确定性组合；之后是可选长期记忆、会话消息与工具说明，历史内部保持原有顺序。
- **FR-016**：日期时间明确时区，来源可替换以供确定性验收；仅将工具说明发送为工具 schema，不将工具执行代码作为提示词。
- **FR-017**：每次上下文构建重新读取指令与已绑定 SKILL.md 正文，不缓存跨构建的正文；配置值、连接和绑定关系仍采用启动快照。
- **FR-018**：显式引用的上下文文件缺失、非法、不可读或越界时在外呼前报错；默认约定的可选 Bootstrap 缺失至少警告，其他 I/O 故障不能伪装为不存在。
- **FR-019**：上下文文件仅从工作区批准范围读取，每次重读重新检查路径/软连接实际目标、文件类型与容量；不展开正文中的环境变量，不执行正文或脚本。
- **FR-020**：工具列表只包含当前 Agent 允许且实际注册的工具；实际执行前仍重新校验身份、参数和 Sandbox 策略，不能以“发送过 schema”代替授权。
- **FR-021**：交付统一工具契约、注册和执行所需的最小能力，所有工具来源共用边界；本轮内置业务工具只包含 http_get，测试工具不得被默认生产注册。
- **FR-022**：http_get 的授权覆盖目标域名/端口/实际地址及请求方法，拒绝未批准本机、私网和元数据服务目标；默认不跟随重定向，测试本机地址仅在隔离测试策略中显式允许；不自动重发。
- **FR-023**：工具边界必须覆盖超时、请求/响应容量、参数和资源限制；未配置的目标默认拒绝，白名单不声称提供操作系统或多租户强隔离。
- **FR-024**：持久记录工具调用成功、失败和拒绝，包含会话、处理、调用标识、工具名称、时间、状态，以及 success/error_message 一致字段；错误说明来自固定安全类别，不持久化任意参数或完整结果正文。
- **FR-025**：工具开始审计必须先提交，成功后才允许执行；执行后的终态提交失败时停止处理并返回结果不确定，不自动修复、补偿或重放。
- **FR-026**：处理期间工具可获取当前 Agent 的配置上下文；正常返回、异常、保存失败均必须清理，后续请求和其他会话不得继承该上下文。
- **FR-027**：会话和长期记忆的访问通过统一 Memory 门面；本轮只实现会话持久化、恢复及长期记忆的可选空能力/测试替身，不依赖完整长期记忆后端交付。
- **FR-028**：处理状态区分运行中、完成、达到上限、失败和中断；只有历史和终态已可靠提交才能返回已完成；同一会话并发请求在执行前拒绝为忙。
- **FR-029**：重启后保留已提交历史，识别未结束处理和未确认工具，不自动续跑或重放；下次用户请求显式开始新处理，排除未闭合工具交换组。

### 关键实体

- **会话**：由运行时创建、绑定 Agent 的稳定身份，包含有序且可恢复的对话记录。
- **处理**：一个用户请求对应的一次完整运行，拥有独立身份、开始/结束时间和终态；同一会话可以先后包含多次处理。
- **模型轮次**：一次被循环接受的模型响应；与 Provider 的物理发送/重试次数不同。
- **消息交换组**：模型工具意图及其全部观察的关联集合，裁剪时不得只留下孤立观察。
- **上下文视图**：系统指令、可选长期记忆、保留历史、当前消息与工具说明的受限发送内容，不等同于全部持久化历史。
- **工具调用与观察**：模型提出的带标识意图，以及经唯一执行边界得到的成功、拒绝、失败或不确定结果。
- **工具审计**：记录一次调用的开始与终态，关联会话、处理和工具标识，与对话正文分开保存。
- **当前 Agent 上下文**：仅在一次处理期间有效的配置视图，结束后必须清理。
- **终止结果**：最终答复、达到上限、明确失败或重启中断；不能把未完成描述为成功。
