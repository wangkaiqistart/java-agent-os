## Clarifications

### Session 2026-10-21

- Q: Agent 的运行配置应放在哪种文件中？ → A: 使用 `.aegisos/agents/<name>/profile.yml` 保存运行配置，`AGENT.md` 保留任务指令；Profile 仅从独立 YAML 加载，不再从 AGENT.md frontmatter 派生，也不新增课程式 profiles 目录作为第二配置源。
- Q: 修改 profile.yml 后，Agent 的运行参数应何时生效？ → A: 本轮只在启动/重启时加载、校验和注册 Profile，修改后重启生效；运行中使用稳定快照，不做监听、每请求重载或动态注册；全局 Provider 连接和凭据仍仅重启生效。
- Q: 课程中的 skills 和 notify_channels 应全部放进 profile.yml，还是沿用项目已有设计？ → A: 选择项目映射：skills 由 Agent 的 skills 目录软连接派生，notify_channels 在 profile.yml 中只保存全局通知注册表的名称引用，其余课程运行字段由 profile.yml 提供；本轮只解析、校验和注册元数据，不执行技能、通知或调度。
- Q: 审计表是否需要新增课程要求的 success 和 error_message 两列？ → A: 新增实际列并保留 status/error_code；STARTED 的 success 为空，SUCCEEDED 为 true，FAILED/REJECTED 为 false；error_message 只保存安全标准说明，迁移旧数据并验证字段一致性，绝不保存厂商原始异常。
- Q: 本轮的 sessionId 只作为调用方追踪标识，还是必须对应已持久化会话？ → A: 由调用方明确提供受限格式的标识，本轮只校验格式并关联审计，不验证持久化会话存在性、不将格式合法视为会话存在或授权证明；新会话入口必填，缺失/非法在外呼前拒绝。旧无会话入口保留为显式未关联兼容模式且不伪造标识；真实冒烟必须走带标识入口。

## 用户场景与测试

本功能的 US-A～US-E 是补齐功能内部的用户故事，不改变项目 US-1、US-2 的编号。场景 ID 用于课程追溯；配置、审计及会话关联均按下文已批准 Q1～Q3 验收。

### 用户故事 A：用配置定义 Agent 的模型选择（优先级：P1）

作为 Agent 配置维护者，我希望从可校验的配置加载并按名称查找 Profile，分别管理全局连接与 Agent 调用参数，使模型选择明确，错误配置可定位。

**优先级理由**：配置到调用的链路是课程当前尚未交付的前置能力。

**独立测试**：使用临时配置目录和本地模型替身，加载合法及非法配置，按名称查找并发起指定模型请求；无需 ReAct、工具执行或真实模型网络。

**验收场景**：

1. **A-01**：**假设**存在符合已批准配置契约的合法配置，含 profile.yml 中的运行字段、skills 目录软连接绑定和通知名称引用，**当**启动加载并按名称查找，**那么**按已批准映射组装的 Profile 字段含义与嵌套数据完整可读，模型选择与配置一致；缺少可选项按契约处理，不触发工具、技能、通知或调度执行。
2. **A-02**：**假设**目录中同时存在合法配置、损坏 YAML、引用未知 Provider 的配置和重名 Profile，**当**加载，**那么**合法且无冲突的 Profile 可查找，非法或冲突条目有不含敏感值的来源及错误类别，不按扫描顺序静默覆盖；全局 Provider 重名继续遵守原来的启动拒绝规则。
3. **A-03**：**假设**配置声明环境变量引用，**当**环境值存在、缺失或为空时分别加载，**那么**有效引用按约定解析，缺失与空值明确报错；凭证仅进入连接所需的受控对象，不进入 Profile 可见信息、日志、审计、异常或报告。
4. **A-04**：**假设**全局层配置两个 Provider 的连接及允许模型，Agent 层明确选择 Provider、模型和温度，**当**经 Profile 发起调用，**那么**只访问选定 Provider，使用选定的允许模型与温度；缺名称、缺模型、未知 Provider 或越过允许模型范围均在外呼前拒绝。
5. **A-05**：**假设**运行期间修改 profile.yml、全局连接配置或环境凭据，**当**重启前后分别发起请求，**那么**重启前继续使用原有 Profile、连接及凭据快照，重启后重新加载并使用有效新配置；新增/删除 Profile 亦仅重启后反映，同一请求及重试不混用不同快照。
6. **A-06**：**假设**本功能涉及的应用配置使用 YAML（当前工作区已有默认、开发、监控及相关测试 YAML），**当**分别使用默认、开发、监控及相关测试配置启动或装配，**那么**原有非敏感配置含义和环境差异保持一致，Provider 绑定与凭证引用正确，仓内示例全部使用 YAML，不依赖残留的同名旧格式文件覆盖结果。

### 用户故事 B：按会话追溯每次模型调用（优先级：P1）

作为审计人员，我希望从会话定位成功、失败和拒绝的模型请求，再区分逻辑请求与每次尝试，能够诊断失败而不接触凭证或完整对话正文。

**优先级理由**：课程要求会话关联，且新增字段不能削弱现有前置审计与结果不确定性语义。

**独立测试**：直接提交带会话信息的 Provider 请求，使用本地模型替身和真实审计存储执行成功、失败、重试及审计故障；无需会话对话引擎。

**验收场景**：

1. **B-01**：**假设**调用方分别以两个格式合法的会话关联标识发起请求，同一标识还发起第二个请求，**当**调用成功或失败，**那么**每条可持久化的记录都关联正确的会话标识；同会话的不同请求具有不同 requestId，其他会话记录不混入，既有记录不被覆盖。
2. **B-02**：**假设**一次逻辑请求允许 2 次重试且先超时再成功，**当**执行，**那么**外呼最多 3 次，每次尝试保留相同 sessionId、requestId 及不同 attemptNo，并保留之前的失败记录；默认未配重试仍最多外呼 1 次。
3. **B-03**：**假设**调用成功、超时、认证失败或在本地被拒绝，**当**审计可写并查询结果，**那么**可以区分成功、失败、拒绝和未结束状态，安全失败原因可读；实际存在 success/error_message 及原 status/error_code，且满足 STARTED→success 空、SUCCEEDED→true、FAILED/REJECTED→false 的一致映射；STARTED/SUCCEEDED 的 error_message 为空，FAILED/REJECTED 为安全标准说明，不能把未结束记录描述为确定失败。
4. **B-04**：**假设**旧数据库含成功、失败、拒绝和未结束记录，**当**通过受版本管理的手工迁移升级并重新打开，**那么**原记录及其结果语义保留，success/error_message 两列真实存在，旧记录按原状态及安全错误类别回填且新请求能存能读；历史缺失的会话信息明确标注，不虚构关联，迁移不依赖运行时自动改表。
5. **B-05**：**假设**某次尝试的前置审计失败，或外呼后终态审计失败，**当**请求执行，**那么**前者阻止该次外呼，后者停止后续重试并报告审计不可用及结果不确定；此前已经发生的调用不被改写为“从未发送”。无法写入时不得声称审计已落库。
6. **B-06**：**假设**使用新会话入口分别提交缺失、空白、非法或格式合法但无持久化会话记录的 sessionId，或使用旧入口不提供标识，**当**提交请求，**那么**新入口的缺失/非法标识在外呼前拒绝且不回显/保存原值；格式合法的标识可用于关联，不查询会话存在性；旧入口进入显式未关联兼容模式，审计关联为空且不自动生成虚假标识。

### 用户故事 C：完整传递工具说明且绝不执行工具（优先级：P1）

作为工具集成者，我希望工具说明转换后各字段含义完整保留，模型返回的工具意图可供上层处理，同时 Provider 不产生工具副作用。

**优先级理由**：课程要求字段逐项验收；漏字段和隐藏执行会破坏后续 ReAct 与 Sandbox 边界。

**独立测试**：准备包含复杂参数的工具说明，捕获发给本地模型替身的请求及返回的结构化调用；工具执行计数始终为零。

**验收场景**：

1. **C-01**：**假设**工具具有名称、描述、对象属性、属性类型与说明、required、嵌套对象、数组及枚举等本功能承诺支持的字段，**当**转换并发送，**那么**逐字段比对语义一致，属性顺序差异不影响判断，原有必填约束及嵌套信息不被丢弃。
2. **C-02**：**假设**说明包含格式错误或本适配器明确不支持的约束，**当**准备调用，**那么**外呼前明确拒绝并给出安全错误，不静默删除字段或放宽约束；支持范围须在验收前公开且与 C-01 一致。
3. **C-03**：**假设**模型返回仅工具调用或文本与多个工具调用混合的响应，**当**Provider 返回，**那么**文本、调用标识、名称、参数及返回顺序保留，工具执行次数为零，Provider 不自行发起下一轮模型请求；配置无法打开自动执行。

### 用户故事 D：用显式冒烟证明真实模型可连通（优先级：P1）

作为验收人员，我希望默认测试安全可复现，并在主动启用真实冒烟时证明配置、凭据、依赖及审计链路真实可用。

**优先级理由**：本地替身测试和安全扫描不能证明真实模型已经调通，课程要求实际成功调用至少一次。

**独立测试**：先执行默认验证确认零真实模型外呼，再以受控环境凭据显式启用冒烟，读取响应与关联审计；无需天气 Demo 或完整 ReAct。

**验收场景**：

1. **D-01**：**假设**环境中即使已有模型凭据，**当**启动应用或运行默认测试、打包和默认 CI，**那么**不会探测或调用真实模型；默认可复现测试继续使用替身或本地存储。
2. **D-02**：**假设**验收人员显式启用冒烟，并提供一个已确认可用的 Provider、模型、凭据引用和格式合法的会话关联标识，**当**执行，**那么**实际发现并执行至少 1 项真实测试，在成功路径只发送 1 次模型请求（本次禁用重试），获得非空响应，新增 1 条会话/请求关联正确的成功终态审计，保留脱敏证据。
3. **D-03**：**假设**显式冒烟缺配置、缺凭据、未发现测试、被跳过、网络失败或审计不匹配，**当**汇总验收，**那么**分别记录 NOT_RUN 或 FAIL 及安全原因，不得记为 PASS；实际运行失败为 FAIL，未实际执行为 NOT_RUN；本课程验收仍未完成。

### 用户故事 E：在保留既有能力的前提下交付可审查变更（优先级：P1）

作为维护者，我希望补齐内容有完整追溯、测试与构建证据，配置和代码说明便于接手，并且原有 Provider 安全行为持续有效。

**优先级理由**：可追溯交付和每个故事的测试、构建是项目既有门禁。

**独立测试**：审查课程追溯表、配置示例与注释，执行现有回归及受影响故事的验证，检查原任务和历史证据没有被改写。

**验收场景**：

1. **E-01**：**假设**完成某个补齐故事，**当**运行其验收及既有回归，**那么**新增场景通过，显式路由、显式模型、重试上限、每次尝试审计、前置审计门槛及敏感信息保护全部保留；该故事的测试与 Maven 构建通过后才开始依赖它的故事。
2. **E-02**：**假设**准备交付，**当**维护者逐项审查，**那么**7 个课程条目均可追溯到要求、成功指标、场景和实际证据；新增/修改的公共契约、配置加载与覆盖、安全边界、审计状态与迁移、重试和冒烟入口具有解释意图及边界的详细中文注释；记录当前真实结果，原 51 项任务与原验证历史保留。

### 边界情况

- 配置目录不存在或为空：Profile 索引为空且有安全提示，不扫描任意工作目录，不在启动时试调用模型。
- 重名 Profile 不得取“最后一个”；缺少全局 Provider 或缺少模型不得回退到默认项。运行配置仅来自 Agent 目录内的 profile.yml；缺少该文件不从 AGENT.md frontmatter 回退派生；profile.yml 若重复声明由 skills 目录负责的技能绑定，应给出安全配置错误，不进行隐式合并。
- YAML 解析必须限制资源消耗并拒绝任意对象实例化等危险输入；嵌套过深、别名膨胀或非法标签明确失败，不执行配置内容。
- 非 Provider 字段此轮仅承载与校验已承诺的数据结构，不因出现 schedules、skills、bootstrap 等配置触发新业务能力。skills 仅由 Agent 本地 skills 目录软连接派生，profile.yml 不得同时声明 skills 作为第二绑定来源；notify_channels 仅保存名称引用，不保存连接、Webhook 或凭据，注册表解析与通知发送留给后续能力。
- 环境引用仅在契约声明的位置解析，缺失值不保留成可用凭据，不将凭据展开到可见 Profile 或错误文本。
- 缺少 temperature 可以保持未指定；提供时只接受实际适配器支持的合法值，不能静默改成另一个值。
- 无 token 用量时仍可成功，未知值保持未知，不推算或补零；工具调用不包含文本时仍按既有契约处理。
- 同会话的多次请求、同请求的重试、不同会话的请求均不得互相覆盖；缺失或非法标识仅记录安全拒绝原因，不回显或持久化原值；格式合规的标识仅表示调用方提供的关联值，不能作为认证、授权或会话已存在的证明。
- 历史无 sessionId 的数据和旧入口兼容调用均明确为未关联，关联值为空；新会话入口的缺失/非法标识拒绝记录同样不保存无效值。新增字段不反向虚构历史关联，也不要求引用会话主记录。
- 审计终态写入失败与进程中断后遗留未结束状态，均不能伪装为已完成；本轮不新增自动重放或恢复外部模型请求。
- 真实冒烟超时或失败不进行隐式重试，不用 NVD 凭据代替模型厂商凭据，不展示完整响应或密钥作为证据。
- 默认构建成功、真实测试类存在、零测试或仅跳过都不能代替真实冒烟成功。

## 需求

### 功能需求

- **FR-001**：系统必须从 `.aegisos/agents/<name>/profile.yml` 加载合法 Profile，并提供按稳定名称查找能力；`AGENT.md` 只提供任务指令，不读取其 frontmatter 作为运行配置，不扫描独立 profiles 目录作为第二来源；启动时不探测真实模型。验收：A-01、A-02、D-01。
- **FR-002**：加载必须隔离损坏、非法和冲突 Profile，提供安全、可定位的错误；其他合法 Profile 继续可用，不按扫描顺序覆盖。验收：A-02。
- **FR-003**：必须对课程全部字段提供逐项映射：name、description、identity、provider（name/model/temperature）、tools、mcp_servers、channels、notify_channels、schedules、bootstrap、settings 由 profile.yml 提供；skills 仅由 Agent 本地 skills 目录软连接派生，notify_channels 只保存全局通知注册表的名称引用。不得静默丢字段、合并第二绑定来源或保存通知凭据；非 Provider 能力只承载元数据，技能执行与通知注册/发送不在本轮范围。验收：A-01、E-02。
- **FR-004**：必须区分全局连接定义与 Agent 调用参数；全局定义连接、凭据引用及允许模型，Agent 明确选择名称、模型与可选温度；禁止缺模型默认选择与越过全局限制。验收：A-04。

### 关键实体

- **Profile**：一个可按名查找的 Agent 运行配置及关联元数据；含模型选择和课程字段映射，不携带可见凭证。唯一运行配置来源为 Agent 目录中的 profile.yml；AGENT.md 提供任务指令，skills 来自 Agent 的 skills 目录软连接，notify_channels 是 profile.yml 内的通知名称引用。
- **全局 Provider 定义**：显式名称、协议适配身份、连接、凭据引用、允许模型和重试上限；遵守原启动快照。
- **会话关联**：调用方提供的受限格式追踪标识；与逻辑请求标识、尝试序号共同定位审计，不能证明真实会话存在或调用权限。新会话入口必填，旧入口/历史数据为显式未关联，本轮无会话存在性校验。
- **模型调用审计**：会话及请求关联、尝试序号、Provider/模型、安全结果和失败原因、耗时、可用用量；success/error_message 兼容列按已批准 Q2 与原状态一致维护；会话关联边界按已批准 Q3：合规标识用于追踪，历史/兼容与无效拒绝记录允许未关联。
- **工具说明与调用意图**：可传递的名称、描述、参数约束和模型返回意图；不包含可执行回调。
- **课程验收证据**：课程条目与页码、FR/SC、场景、批准偏差、实际命令与测试统计、脱敏结果及 PASS/FAIL/NOT_RUN。

## 假设与依赖

- sessionId 的格式默认约定：1～64 个 ASCII 字符，首字符为字母或数字，后续仅字母、数字、下划线或连字符，区分大小写，不 trim 后接受；空白、超长或含其他字符均拒绝。该范围兼容课程示例式标识及 UUID，只是本轮可验收的格式约束，不是会话存在性校验；它是用户选择“受限格式”后的明确默认细化，不属于用户回答原文。
- 环境引用的默认补充约定：沿用全局 credential-ref: env:变量名；profile.yml 仅在非敏感的 provider.name、provider.model、provider.temperature 上支持 ${ENV}，启动时按目标字段规则解析/校验，缺失、空值或非法值使该 Profile 无效且错误不输出值。其他正文与元数据不递归展开环境变量，技能绑定只来自目录。这是根据既有凭据契约与课程需求补充的明确默认，不属于用户回答原文。
- 原 US-1 是复用基础；其 91 项测试及安全门禁为历史结果，后续改动后必须重新验证。不能沿用旧报告证明本功能涉及的 YAML 配置或新审计字段已通过。
- 可独立使用本地模型替身验证路由、失败、审计与字段转换；真实厂商网络只用于显式冒烟。真实成功验收依赖可用厂商、模型、受控凭据及网络，具体选型在 plan 中核实并记录；此轮不把示例名称当作已验证厂商。
- 真实冒烟厂商凭据与 NVD 漏洞库凭据完全不同；此轮规格生成不读取或使用任何密钥。缺少真实模型条件时允许完成可独立工作，但整体验收保持未完成。
- Profile 的名称、模型选择与元数据加载是本轮范围；并不因此承诺课程后续章节中的 Skill 执行、通知注册、定时调度或动态 Agent 管理能力。
- Q1～Q3 均已澄清，后续 plan 按已批准的来源、状态与会话关联边界设计，不重新引入未批准的双配置源、热更新或会话存在性依赖。
- 本轮不预选配置加载库、数据库迁移组件、测试发现插件、Java 方法签名或新增模块；这些由后续 plan 在既有边界内确定。
