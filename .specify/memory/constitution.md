# AegisOS 项目开发宪法

## 核心原则

### 一、模块边界与依赖方向

AegisOS 必须保持九个 Maven 模块的清晰边界：
`aegisos-core`、`aegisos-provider`、`aegisos-memory`、`aegisos-tool`、
`aegisos-channel-cli`、`aegisos-web`、`aegisos-storage`、`aegisos-cli` 和
`aegisos-boot`。核心领域契约必须独立于交付、存储和 Provider 实现。依赖必须指向稳定契约；当存在公共契约时，模块不得直接访问其他模块的内部实现。每个模块都必须能够在 Maven reactor 中独立编译和测试。

### 二、显式 Provider 选择与 ReAct 归属

Provider 选择必须使用配置或调用请求中明确、稳定的 Provider 名称。AegisOS 不得通过扫描任意同类型 Bean 来推断 Provider。ReAct 循环必须由 AegisOS 自己负责，并且模型调用、推理步骤、工具决策和终止条件必须可观察。Spring AI 可以用于模型客户端、协议转换和工具 schema 生成，但必须禁用自动工具执行，避免同一个工具被执行两次。

### 三、统一 Memory 门面与沙箱工具执行

所有 ReAct 记忆访问必须经过 `MemoryService` 统一门面。会话上下文和长期记忆不得散落在循环实现中。所有内置 Tool、MCP Tool 或 Java 插件 Tool 都必须适配统一的 `AegisTool` 契约，并经过 Sandbox 策略执行。Tool 白名单只是策略检查，不得被描述或实现为完整的多租户隔离边界。

### 四、可测试的用户故事（User Story）与构建验证

每个用户故事（User Story）都必须定义可独立测试的验收场景。用户故事完成时必须包含验证其行为所需的测试，并且必须通过适用的 Maven test 和 package 检查，之后才能开始依赖它的用户故事。契约变更、共享 schema、Provider 集成、Memory 行为、Tool 执行和 Web 端点都必须在边界处有聚焦测试。单元测试通过不能替代 Maven reactor 构建成功。

### 五、安全、可观测与增量交付

API key、Token、密码、Webhook 凭证和完整连接字符串不得写入源码、文档、`AGENT.md`、生成物、日志或 Git 历史。运行时敏感信息必须来自环境变量或经过批准的密钥存储。核心执行必须持久化 `llm_calls` 和 `tool_invocations` 审计记录，不能只依赖日志。变更必须以小步、可审查的增量交付；在代码和验证提供证据之前，不得将计划行为描述为已实现。

## 架构与安全约束

- 基线运行时必须使用 Java 21、Maven 和项目批准的 Spring Boot 版本。
- 公共接口必须在模块边界定义，并在依赖模块使用前完成文档说明。
- Sandbox 决策必须覆盖 Tool 身份、参数、授权、超时、资源限制、失败处理和审计结果。
- 配置重载行为必须在功能规格中明确；实现必须采用一种有文档依据的重载契约，不得混用“仅重启生效”和“每轮重新加载”两种语义。
- Memory 范围和后端选择必须按功能记录。项目默认契约从 `MEMORY.md` 开始；其他后端必须有明确设计决策和测试。

## 开发流程与质量门禁

- 跨模块或面向用户的工作必须遵循 Spec Kit 顺序：`constitution` → `specify` → `clarify` → `plan` → `tasks` → `implement`。
- 生成的 `spec.md`、`plan.md` 和 `tasks.md` 是功能工作契约。计划必须说明受影响模块、接口、数据变更、测试和可运行的验证路径。
- 每个用户故事（User Story）都必须作为独立、可审查的增量实现和验证。聚焦测试、Maven 构建或宪法检查失败时，必须阻止后续依赖故事开始。
- 报告完成前，实施者必须运行相关测试、`mvn clean package`，并对功能产物执行一致性检查。
- 实现后发现的缺口必须通过收敛流程记录，并通过后续实施轮次完成。

## 中文文档约定

- 后续新增或修订的 `spec.md`、`plan.md`、`tasks.md`、检查清单、架构说明、开发指南和用户可见项目文档，必须尽量使用简体中文。
- Java 类名、模块名、配置键、命令、协议名称、代码标识和外部产品名可以保留英文原文；首次出现时应使用中文说明其含义。
- 代码、测试、日志字段和外部 API 的机器可读内容遵循既有技术约定，不因中文文档要求强行翻译。

## 治理

本宪法是 AegisOS 的开发治理契约。修改原则或强制性约束时，必须更新本文件，附带同步影响报告，说明兼容性影响，并更新受影响的功能产物。Pull Request 和实施评审必须核对模块边界、安全规则、测试和 Maven 构建门禁。

宪法版本遵循语义化版本：删除或重新定义强制性原则时升大版本；新增或实质扩展原则或治理章节时升次版本；只澄清文字且不改变强制行为时升补丁版本。项目维护者批准修订，最新版本和修订日期必须在文件末尾可见。
